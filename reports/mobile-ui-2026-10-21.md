# Mobile UI audit — 21 October 2026

The reported game header overlap was reproduced locally on baseline `1dcbbef`. This report records verification before release. Shipping was subsequently authorized; Git history and the production receipt establish the release state.

| Finding | Current evidence and fix |
| --- | --- |
| Back button overlaps score | At 390×844, Back occupied x=16–146.625 and the score x=130.25–259.766, with overlapping vertical ranges. The score now has its own row on compact/touch layouts, with 10px clearance beneath the toolbar. |
| Back and Sound use different positions | Their original top offsets were 14px and 24px on phones. The host now shares the Back button's measured bounds with the iframe. Measurements use the fixed container so the entrance transform cannot introduce a transient 10px error. A ResizeObserver handles button/font size changes and is disconnected on disposal. |
| Stars inherit score typography | The generic HUD span selector overrode the star meter's intended 12px type. Its selector now applies that size consistently. |
| Short landscape cards collide with controls or clip their action | Cards now fit between the top and bottom rails. At 568×320, a more compact result layout and pause spacing keep the entire primary button visible; scrolling remains available for exceptional content sizes. The verifier tests the button's full bounds and actual hit area, not just the card's bounds. |
| Phone instructions mention a keyboard | Start/pause instructions now match the visible controls, and update when the responsive layout changes. Compact landscape phones retain touch controls. |
| Project paging targets are too narrow | Next/Previous measured approximately 40.83px wide. They now have a 44px minimum in both dimensions. |
| Contact targets shrink after rotation/tablet breakpoint | Links measured approximately 18.9px tall at 721px and 844px widths. The existing 46px phone target rules now also cover tablet widths and coarse pointers. |

The header fix lives at the host/iframe boundary in `site/public/puff-up/entry.js`; the game still owns its score, sound, pause/results, input, and rendering. Layout checks did not require changes to the game's physics or the portfolio's section order.

## Verification

The local production server used `TRAINING_FIXTURE=1`, port 4361, and an isolated build directory. All browser automation used Umbra scratch profiles and WebKit. Source SHA-256 hashes and both build IDs are saved in `output/mobile-ui-2026-10-21/artifact.json`.

Final results: **451/451 mobile UI checks**, **22/22 game-route checks**, **41/41 game integration checks**, **107/107 whole-site checks**, and **49/49 game tests** passed. Lint, the final production build, JavaScript syntax checks, and `git diff --check` also passed. The temporary server and scratch browser profiles were stopped after verification. Next's generated `tsconfig.json` and `next-env.d.ts` changes were restored to their original contents.

The added `site/scripts/verify-mobile-ui.mjs` exercises:

- Game at 320×568, 360×640, 375×667, 390×844, 430×932, 720×1024, 721×1024, 844×390, 667×375, 568×320, and desktop 1440×900.
- Pausing, naturally reaching visible game-over results, retry, sound, return to portfolio, and preserving/resuming the same game through portrait/landscape rotation.
- A frozen six-digit score and three-digit streak as explicit layout fixtures, plus a simulated 59px host top inset while the iframe inset remains zero. These fixtures are not gameplay achievements or physical-device evidence.
- All three intro scenes, all nine project dialogs and their paging/close controls, photo details, the training invitation, training page, and return navigation across eight mobile/tablet sizes.
- Horizontal overflow, minimum control dimensions, browser errors, control collisions, and hit testing at ±21.5px around game controls.

Existing game-route and integration verifiers cover direct entry/refresh, browser Back/Forward, immediate reversal during return, invitation font stability, focus/scroll restoration, steering, and cancellation. The whole-site verifier additionally checks photo shuffle, preview routing, fonts, résumé downloads including byte equality, and expected HTTP status codes.

This is local WebKit verification with mobile viewport/user-agent emulation. Real iPhone Safari chrome, hardware touch behavior, and actual device safe-area values were not tested. Coarse-pointer rules share the compact layout implementation; Umbra's viewport emulation does not make its desktop WebKit pointer coarse. Training fixture data verifies layout and navigation, not current account data. The changes passed independent pre-ship review.
